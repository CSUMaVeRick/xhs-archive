# 📕 XHS Archive · 小红书笔记归档

> 一个把小红书笔记「一键保存到本地」的浏览器插件，图片、视频、文字全部存到你自己电脑的文件夹里，**不需要联网也能看**。纯本地运行，离线可用，没有服务器、不上传任何数据。

---

## 它帮你做什么？

逛小红书看到想收藏的内容，点一下就能存到本地：

- ✅ **图文 / 视频笔记**都能存
- ✅ 自动整理成 **日期 → 笔记文件夹** 的结构
- ✅ 额外生成一个 **离线可看的网页卡片**（`index.html`），双击就能像刷小红书一样看
- ✅ 保留**标题、作者、发布/归档时间、话题标签、IP 属地、点赞/收藏/评论/分享数、正文**等元数据
- ✅ 每条记录自带**溯源自描述**：抽取路径（API / 页面状态 / DOM 回退）、字段来源、以及**缺失字段清单**，让样本事后可自证
- ✅ 可在管理页**人工标注**：确认关键词、补录排序方式、贴标签、标记排除，并导出成分析用的 CSV / JSONL
- ✅ 视频可按 **最高画质 / 1080P / 720P / 仅封面** 存储
- ✅ 自带一个**归档管理页**：搜索、浏览、离线预览所有已归档的笔记
- ✅ 在笔记页右下角有个**悬浮工具栏**，不打扰你浏览

归档之后你的笔记就是一堆**完整的文件夹**，图片、视频、文字都在里面，不怕原帖删除或失效。

## 支持的浏览器

使用 **Chrome 内核**的主流浏览器均可：

- Google Chrome
- Microsoft Edge
- 其他基于 Chromium 的浏览器（如 Brave）

> 依赖浏览器底层的「文件系统访问 API（File System Access API）」，**Firefox / Safari 暂不支持**。

## 怎么安装？（一次性，约 30 秒）

1. 下载/克隆本仓库到本地一个**不会被删除**的文件夹。
2. 打开浏览器，输入 `chrome://extensions` 并回车。
3. 打开右上角的 **「开发者模式」** 开关。
4. 点击左上角的 **「加载已解压的扩展程序」**。
5. 选择本项目文件夹（就是包含 `manifest.json` 的那个文件夹），完成。

现在浏览器右上角会出现一个 📕 图标。

> ⚠️ 不要移动或删除解压出来的文件夹，否则扩展会失效。
> 如果修改了代码，回到 `chrome://extensions` 点一下扩展卡片上的「重新加载」即可生效。

## 怎么使用？

### 方式一：在笔记页直接归档（最方便）

打开任意一篇小红书笔记，页面右侧会出现一个**竖向细长工具栏**：

- **📥**：一键归档**当前**这篇笔记
- **⟨**：展开/收起详情面板

点击 📥 后会自动把该笔记保存到你的归档目录。

> 第一次使用需要**选择一次归档目录**，之后默认走这个目录。

### 方式二：通过弹窗归档

点右上角的 📕 图标，在弹窗中：

1. 点击 **「选择 / 切换归档目录」**，挑一个放笔记的文件夹（会**记住**，下次不用重选）。
2. 选好 **视频保存画质**。
3. 点击 **「归档当前笔记」**。

### 方式三：开放「归档管理」页

点弹窗里的 **「打开归档管理」**（或右键扩展图标 → 选项），支持：

- 选择归档根目录（需要**写入权限**，用于保存人工标注），自动遍历并列出所有已归档笔记
- **笔记视图**：按**标题 / 标签 / 作者 / 关键词 / 标注备注**搜索，按标签筛选，可隐藏已排除的样本
- **作者视图**（顶部标签页切换）：列出所有存过的作者——粉丝数 / 关注数 / 平台笔记数 / 获赞与收藏 / 认证 / 属地 / **我们归档了他几篇** / 最近观测时间；可按粉丝数、归档笔记数、最近观测排序，也可只看"有归档笔记的作者"。点任意一行看这位作者的档案和笔记清单（点笔记直接进预览）
- 点击任意笔记 → 右侧抽屉在线预览（图片、视频、数据统计、原帖链接、数据来源标记）
- **人工标注**（见下方「方式四」）
- **导出**：笔记 `export.csv` / `export.jsonl`、作者 `authors.csv`

> ⚠️ 首次使用请点 **「选择归档目录」** 并授予写入权限。若之前是只读打开的，保存标注时会提示重新授权。

### 方式四：给样本贴标签（人工标注）

在笔记页浏览检索结果时，插件会**自动记录检索词**：从检索请求的 URL 里读（页面自己发出的请求，插件不构造新请求；响应内容只在"搜索结果页粗糙采集"里读，见上一节），地址栏有 `keyword` 时也会兜底读一次；归档后到管理页补齐人工判断即可：

1. 点列表里任意一篇 → 抽屉打开，**左边是笔记卡片**（标题、统计数据、标签、正文、图片/视频、原帖链接），**右边是简易标注面板**
2. **标签**：从词表里选或新填；点「管理标签词表」维护固定词表，保证编码一致
3. **备注**：编码过程中的判断记在这里
4. **标注人**：谁做的编码（会记住上次填的）
5. 点「保存标注」写入该笔记目录下的 `annotation.json`
6. 需要批量处理时用列表上方的工具栏：**批量加标签 / 批量去标签 / 批量设排序 / 批量排除 / 取消排除**
7. 需要分析时点 **「导出笔记 CSV」** 或 **「导出 JSONL」**，写到归档根目录的 `_meta\` 下

> 📌 **检索词与话题标签是两回事**，而且插件的 `_source` 记录的是第三件事：
>
> | | 记在哪 | 含义 |
> | --- | --- | --- |
> | **来源** | `_source.type` | 你是从哪个入口拿到这篇的：搜索 / 作者主页 / 笔记内推荐 / 推荐流 / 直接打开。判定依据记在 `_source.typeSource`（`xsec_source` / `source` / `url_keyword` / `url_path`），`raw` 是平台参数原话 |
> | **检索词** | `_source.keyword` | 搜索时才有的那个词（仅 `type === 'search'`） |
> | **话题标签** | `tags` | 笔记作者自己打的 `#标签` |
>
> 三者的区别在于：话题标签是**作者的自述**；来源与检索词是**你的抽样方式**——只有它们能回答"这批样本是怎么来的"。来源由平台在网址里提供的参数自动判定，不需要你填。注意平台给检索结果页也挂了 `source=web_explore_feed` 这种版式水印，所以判定按 `xsec_source` → 检索页路径/`keyword` → `source` 的可信度排序，不会把检索页当成推荐流。

人工标注写在每篇笔记目录的 `annotation.json` 里，**永远不会修改** `metadata.json` —— 原始观测记录保持不可变。

### 在搜索结果页先粗采一批（用来挑哪篇值得细致归档）

逐篇归档是"看到一篇、存一篇"。如果你先想看清一批检索结果里都有什么，用这个：

1. 在小红书**搜索结果页**（先搜好词、选好筛选）点扩展图标打开弹窗
2. 填 **滚动次数**（默认 5）与 **间隔毫秒**（默认 2000，不建议低于 1000）
3. 点 **「开始采集」**。插件会替你往下滚，每滚一段就记录页面这一批新结果
4. 页面上会出现一个浮条，显示"已滚 N/M 次 · 已采 X 条"，**随时可以点「停止」**——关掉弹窗也能停，浮条一直在
5. 采完（或你停掉）之后，回管理页的 **「检索批次」** 标签页：点开某一批 → 看到卡片墙 → 勾选想要的 → **「导出勾选 JSONL / CSV」**

存下来的东西：

```
归档目录/
└── searches/
    ├── 新传论文发表_20260917-1617_general.jsonl   # 首行是批次信息，后面每行一条命中
    └── 新传论文发表_20260917-1617_general/        # 同名目录，里面是封面图
        ├── 001_6a39f801.jpg
        └── ...
```

每行一条记录，含：**位次**（第几条）、页码、标题、作者 id 与昵称、点赞/收藏/评论/转发数、发布时间、是不是视频、封面、**这本笔记的完整图片地址**、以及能点开的原帖链接。

几条刻意的取舍：

- **它是抽样框，不是样本。** 粗糙记录只有卡片级信息（没有正文、没有评论、没有原图），用途是"挑出值得细致归档的"，不是替代归档
- **位次只在同一批里有意义**：它是"这次搜索里第几眼看到它"。同一次搜索翻了 19 页、共 380 条都是同一批；换个词、改个排序就是新的一批
- **不记"你有没有赞过、收藏过"**：接口里有这两个值，但那是你账号的行为而不是笔记属性，在数据进桥之前就被丢掉了
- **重复出现的笔记只留第一次的位次**，重复次数记进批次信息
- **不做自动翻页**：滚几次是你设的，插件不替你决定采多少，也不设上限（请自行控制频率）
- **封面上限**：只下封面，不下整本图片集。下不到的留空（`coverFile: null`），不假装有图
- **采集和落盘分开**：采集在网页里跑（所以关掉弹窗它继续），写文件在弹窗里做。弹窗关着的时候数据暂存在浏览器本地，**重新打开弹窗就会自动写入**，不会丢

> ⚠️ 这一条与"逐篇归档不自动滚动"的承诺不冲突，但确实是插件里唯一会替你滚动的功能：**只有你显式设了次数、点了开始，它才滚**，且随时可停。

### 想让「作者粉丝数」被记录？

粉丝数是**时间敏感变量**，插件只在你**实际打开过该作者主页**的时候顺手记下（纯被动读取，不额外发请求）。操作上就是：在笔记页点一下作者昵称进主页，再回来归档即可；同一浏览器会话内之后归档该作者的其他笔记也会自动带上。

没看过主页的记录，这四个字段保持 `null` 并登记在 `_fieldsMissing` 里——**不会猜**。粉丝数缓存在浏览器本地（最多 300 位作者）。

### 把作者单独存一份（authors.json）

如果你把**作者**当成独立的分析单元（而不只是笔记的附属），有两种用法：

**在作者主页上**：面板按钮显示 **「保存当前作者」**，点一下就存这一位。信息直接来自页面上的可见文本（昵称、小红书号、IP 属地、关注/粉丝/获赞与收藏、简介），**不依赖任何接口请求**，所以整页直开也能存。

**在其他页面**：按钮显示 **「保存已缓存作者 (N)」**，N 是你在浏览器里逛过的作者数（打开过主页就会被动记下），点一下把它们一起合并进 `authors.json`。

- **不做任何自动跳转**：数据只来自你实际打开过的作者主页，纯被动读取
- **不会保存你自己**：登录账号的信息（页面自己会请求的 `user/selfinfo`）只被用来把"本人"从采集里排除，不会被写成作者；在你自己主页上点按钮也会明确提示并拒绝
- 一人一条记录：粉丝数、关注数、笔记数、获赞与收藏、简介、认证、属地、小红书号
- **值变了才留历史**：同一组数值反复保存只刷新"最近确认时间"，所以文件不会因为多点几次而膨胀；真的涨粉了才会往 `history` 里存一份旧快照
- **你手工加的字段不会被覆盖**（比如给某位作者加个 `"myLabel": "重点作者"`），插件只重写它认识的键
- 管理页有 **「导出作者 CSV」**（宽表，一人一行，`historyCount > 0` 说明这位作者的数值变过）

```
D:\xhs-archive\
├── authors.json        ← 作者表（KEY = userId）
├── _meta\              ← 导出产物
└── 2026-09\            ← 笔记归档
```

## 归档后长什么样？

假设归档根目录是 `D:\xhs-archive`，归档日期是 `2024-06-01`，笔记 id 为 `64a1b2...`，标题为「周末露营好物」：

```
D:\xhs-archive\
├── _meta\                        ← 导出产物（点「导出 CSV / JSONL」后生成）
│   ├── export.csv
│   └── export.jsonl
└── 2024-06\                      ← 归档月份
    └── 2024-06-01\               ← 归档日期
        └── 64a1b2..._周末露营好物\   ← 笔记文件夹（id + 标题）
            ├── metadata.json     ← 完整元数据（JSON，机器写入，不可变）
            ├── annotation.json   ← 人工标注（关键词 / 标签 / 排除 / 备注，管理页写入）
            ├── comments.json     ← 评论（采到多少存多少，如实标注是否完整）
            ├── index.html        ← 离线可看的卡片页，双击即可浏览
            ├── images\           ← 图片（按顺序命名）
            │   ├── 01.jpg
            │   ├── 02.jpg
            │   └── ...
            └── video\            ← 视频（可选）
                └── video.mp4
```

打开某个 `index.html` 就能离线查看该笔记 —— 即使原帖已被删除。

`metadata.json` 里以下划线开头的字段用于**样本自证**，分析时建议先看它们：

| 字段 | 含义 |
| --- | --- |
| `_extraction` | 抽取路径（`API` / `INITIAL_STATE` / `DOM`）、`noteIdMismatch`（数据是否与页面 noteId 一致）、页面 URL、容器 |
| `_source` | **来源（抽样框架）**：`type` 是入口（`search` 搜索 / `profile` 作者主页 / `related` 笔记内推荐 / `feed` 推荐流 / `direct` 直接打开），`raw` 是平台参数原文，`typeSource` 是判定依据；**`keyword` 只在 `search` 下才有值**。`sortOrder`/`resultRank` 当前恒为 `null` |
| `_publishTimeSource` | `api_timestamp` / `dom_absolute` / `dom_relative` / `missing`；相对时间会同时留 `_publishTimeRaw` 与观测时刻 |
| `_tagSource` | `api_taglist`（平台话题）还是 `dom_hashtag`（正文里的话题），两者语义不同 |
| `_statsSource` | `api` / `dom` / `missing`；`missing` 时统计数是 `null` 而**不是** 0 |
| `_author` | 作者：昵称、id、主页链接；`fansCount` / `noteCount` / `bio` / `verified` 只有在**你看过该作者主页**之后才会被补齐（见下方说明） |
| `_imageOk` / `_imageFail` / `_videoOk` | 媒体实际下载成败，归档结束时补写；`imageFail > 0` 就说明这条记录缺图 |
| `_commentsMeta` | 评论摘要（采到几条、共几条、是否完整）。评论正文在同目录的 `comments.json` |
| `_fieldsMissing` | 该条记录缺哪些字段，分析前先按它筛样本 |
| `_schemaVersion` / `_pluginVersion` / `_captureId` | 数据契约版本、插件版本、本次抓取 id |

## 设置项

在扩展弹窗里可以调整：

| 选项 | 说明 |
| --- | --- |
| **视频保存画质** | `最高画质` / `1080P 高清` / `720P 标准（省空间）` / `仅封面（不下载视频，最省）` |

## 它是怎么工作的？

纯前端，没有后端。核心逻辑大致是：

1. **抓取数据**：拦截页面请求，从小红书返回的笔记 API 数据中提取结构化信息（`content/network.js`）。
2. **多重兜底**：如果 API 拿不到，依次回退到页面里的 `__INITIAL_STATE__`（直开链接的笔记页是服务端渲染，数据只在页面自己的变量里，由插件的页面环境部分读出来再传回）、再到直接扫描 DOM（`content/extract.js`），尽量提高成功率、抗改版。**走的是哪条路径会写进 `metadata.json._extraction`**，事后可查。
3. **下载到本地**：用浏览器的「文件系统访问 API」让你**选一次目录**，然后把图片、视频、`metadata.json`、离线卡片页直接写进你选的文件夹（`content/archive.js` / `popup.js`）。
4. **人工标注**：管理页只写 `annotation.json`，与归档路径的 `metadata.json` 物理隔离，互不覆盖（`manage.js`）。
5. **防盗链处理**：通过 `declarative_net_request`（`rules.json`）给图片 CDN 请求补上 `Referer` / `Origin`，绕过图片 hotlink 限制，不弹浏览器下载框、静默完成。

### 项目结构

```
xhs-dev/
├── manifest.json            # 扩展配置（Manifest V3）
├── rules.json               # 防盗链规则（给 CDN 补 Referer/Origin）
├── background.js            # 后台 Service Worker（仅消息中继；归档在页面/弹窗内完成）
├── popup.html/.js/.css      # 扩展弹窗（选目录、设画质、采集者标识、一键归档）
├── manage.html/.js/.css     # 归档管理页（搜索 / 浏览 / 标注 / 批量贴标签 / 导出）
├── docs/
│   ├── DESIGN.md            # 采集可信度与人工标注的设计文档（数据契约在这里）
│   └── DESIGN-search-hits.md # 搜索结果页粗糙采集的设计文档（实测数据与契约）
└── content/
    ├── schema.js            # 共享常量：schema 版本、字段缺失计算、CSV 助手、批次契约
    ├── network.js           # 拦截 fetch/XHR，捕获笔记 API 数据与检索结果批次
    ├── extract.js           # 数据抽取：API > __INITIAL_STATE__ > DOM + 溯源字段注入
    ├── search.js            # 检索页粗糙采集：滚动、去重编号、缓冲、页面浮条
    ├── archive.js           # 页面内直接归档（File System Access）
```

## 常见问题

**Q：为什么有时候「归档」提示抓不到笔记？**
小红书页面结构会不定期改版，旧的选择器可能失效。可先**在详情面板里展开「调试信息」**看看走的是哪条抓取路径（API / INITIAL_STATE / DOM），多半能定位问题。

**Q：评论会一起存下来吗？存多少？**
会。评论存在同目录的 `comments.json`：**你在页面上加载出来多少，就存多少**——打开笔记时的首屏评论，加上你往下滚时页面自己加载的后续页。插件**不会自动滚动**去抓全（那属于自动化操作，风险和你自己不想踩的一样）。

所以每条归档都会如实标注完整性：`_commentsMeta.complete` 用**保守判据**——必须"平台说没有下一页"**且**"采到的条数不少于平台声明的总数"两个条件同时满足才为 `true`，否则一律 `false`。`capturedCount` / `topLevel` / `replies` / `declaredTotal` 都写出来供核对。

⚠️ 特别注意：**平台的"共 N 条评论"把回复也算在内，而回复需要点开「展开 N 条回复」才会加载**。所以你会看到"平台说 11 条、我们采到 7 条"这种情况——那不是 bug，是确实没采全（差的正是没展开的那几条回复），`complete` 会是 `false`。分析时**不能把不完整的评论当全量**用。

**想让某一篇的评论采全**：在扩展弹窗里把 **「评论采集」设为开启**，然后在笔记页面板的 **「展开评论」** 上点一下，右边下拉选展开范围：

- **前 3 / 5 / 10 / 20 条回复** → 只展开这么多处
- **全部展开** → 把能点到的「展开 N 条回复」「展开更多回复」逐个点开，**并会自动处理一层层往下展开的回复链**（每次点击后重新扫描页面）；仍受 60 次 / 3 分钟的硬上限保护
- 展开过程显示进度（剩余几处、评论从几条变成几条），**随时可以再点一下按钮停止**
- 面板上还会多一行 **「评论 7 条（共 11 · 未完整）」**——这就是判断"还要不要再展开"的依据；数字对上时会显示「完整」
- 如果此刻没有可点的「展开」了，它会如实说「此刻没找到『展开』按钮」并提示可以稍等再点一次，而不是默默无反应、也不替你断言"已经全了"（更深的回复是异步加载的，可能来得比等待窗口还慢）

这是插件里**唯一一处会替你点击页面**的功能：默认关闭、逐篇由你手动触发、可以限定范围、可以随时停止。日常采集完全用不到它。

每条评论记：内容、作者昵称与 id、点赞数、发布时间、IP 属地、父评论 id（子评论压平后靠它归组）、以及 `isAuthor`（这条是不是笔记作者本人回复的）。

**Q：为什么有些笔记的点赞/收藏数是空的？**
看面板的「抽取来源」：显示 `DOM` 就说明两条数据通路（接口响应、页面自带的初始数据）都没命中——那篇的统计数与属地就会空着，并如实登记在 `_fieldsMissing` 里，不会编一个数字。

**Q：提示「数据与页面 noteId 不一致，已禁止归档」是什么意思？**
说明插件手里最新的数据仍是**上一篇**笔记的（页面详情还没加载完就点了归档）。这是**故意的拦截**——否则会把 A 的元数据写进 B 的目录，事后无法发现。等 1-2 秒再点即可。

**Q：`metadata.json` 里的 `_fieldsMissing` 是什么？**
该条记录缺失的字段清单（例如 `author.fansCount`、`stats.shareCount`、`search.resultRank`）。作者粉丝数/笔记数/简介/认证**不在小红书的笔记详情接口里**，只在作者主页，且主动请求需要平台签名，因此当前一律记为缺失而不是猜一个值。统计数为 `null` 表示"没抓到"，`0` 才是真的 0。

**Q：管理页保存标注时提示「当前目录为只读」？**
人工标注要写 `annotation.json`，需要目录的写入权限。点右上角 **「选择归档目录」** 重新选一次并授权即可（旧的只读句柄无法提权时会走到这个提示）。

**Q：归档目录换了电脑或清了浏览器数据，之前选的目录还有效吗？**
目录「句柄」保存在浏览器本地的 IndexedDB 里。如果浏览器数据被清、或换电脑，重新选一次目录即可；已经归档到磁盘的文件不受影响。注意：**页面内归档和弹窗归档用的是两套句柄**（一个存在页面源、一个存在扩展源），所以两个入口各选一次同一个目录最稳妥。

**Q：可以批量归档吗？**
归档当前是**逐篇**的（「当前这篇笔记」）。但**批量标注**已经支持：管理页多选后可以批量贴标签、批量排除。

要"批量"地从一批搜索结果里挑样本，用**粗糙采集**（见上文）：它批量记的是**线索**（标题、作者、数据、封面、图集地址、原帖链接），不是笔记正文。挑完再逐篇归档——这也是它存在的意义：把"哪些值得存"这个判断提前到只花几十秒的一步。

**Q：视频保存失败 / 只有封面？**
常见原因是该视频没有能稳定下载的地址（尤其是刚发布、或分辨率选项缺失）。可在弹窗里设为「仅封面」或「720P 标准」再试。注意「仅封面」模式下 `_videoFile` 为 `null`，离线卡片不会出现坏掉的播放器。

**Q：会不会上传我的数据 / 需要登录？**
不会。所有数据都在**你本地浏览器和本地文件夹**里，**不经过任何服务器**。浏览小红书仍要正常登录小红书账号，但这是小红书自己的登录，与插件无关。

插件**不读取你的私信、聊天、关注列表与搜索历史**：那些接口在拦截层被显式排除（`content/network.js` 的 `SKIP_URL_RE`），埋点与风控请求同样跳过。它只处理可能包含笔记内容的接口，加上页面自己已经渲染出来的公开信息。

**Q：采集时会不会被平台识别为自动化？**
逐篇归档**只被动读取页面自己已经发出的响应**，不额外构造请求、不自动翻页、不自动滚动；检索词也只在页面自己的检索请求 URL 里读（不读私信、不读检索历史）。请保持人工浏览的节奏。

唯一的例外是**搜索结果页的粗糙采集**：它确实会替你滚动。所以它做成了"由你设次数与间隔、显式开始、随时可停"，默认 5 次、建议间隔不低于 1 秒——**请自行控制频率**，插件不设上限，也就不替你兜底。

**Q：粗糙采集和逐篇归档的数据会混在一起吗？**
不会，是刻意分开的。粗糙采集只写 `searches/` 下的清单与封面，不碰每篇笔记目录；管理页的「笔记」视图也看不到它们（那是「检索批次」标签页的事）。所以逐篇归档的 `metadata.json` 里 `resultRank` 仍然是 `null`——这个值是"粗糙采集"那边的事，两边没有互相回填。
